## 3. 오전 — 실차 경험을 학습 실험에 반영

### 3.1 시작 문제와 작업 범위

사용자의 목표는 **라이다만 읽는 학습 모델을 실제 차량에 넣어 처음 보는 트랙에서도 빠르고 충돌 없이 주행**하는 것이다. 11월 10일 실제 시험에서 감속 지연, 반복 정지, 전류 보호 관련 문제가 있었으므로, 6m/s 전문가 데이터로 다시 학습하기 전에 차량 응답 차이를 정리하기로 했다.

이 단계에서는 사용자가 실차 측정이 불가능하다고 밝혔으므로, 추가 측정 없이 할 수 있는 **기존 자료 재검토와 시뮬레이션 변경**을 진행했다. 같은 날 오후에는 사용자가 실제 차량 시험을 시작하여 작업 범위가 실차 배포·시험으로 이어졌다.

### 3.2 제동·회생·전류 문제 정리

차량 제어는 목표 속도를 ERPM으로 변환하여 VESC에 전달한다. 목표 회전수를 낮추는 명령과, 그 목표를 맞추는 과정에서 VESC가 발생시키는 제동 전류는 구분해야 한다.

기존 기록을 재검토한 [제동 보고서](braking_review_20261112.json)에는 다음 해석 한계를 남겼다.

- 배터리 입력 전류 음수와 충전 누적 에너지 증가는 VESC DC 입력 측의 회생을 뒷받침한다.
- 모터 전류 음수만으로 배터리에 실제 에너지가 반환됐다고 단정하지 않는다.
- 기록된 전류는 상태 패킷의 평균값이므로 순간 과전류 피크를 재구성하지 못한다.
- 명령과 상태 메시지 수신 시각은 비동기다. 수신 시각을 제어기 내부의 정확한 실행 시각으로 보지 않는다.
- ERPM 반응은 관찰할 수 있지만 실제 지면 속도·미끄러짐·물리 감속 한계를 식별한 것은 아니다.
- “목표 RPM이 급격히 낮아져 음의 전류 한계에 걸린 것이 모든 정지의 원인”이라고 확정하지 않았다.

### 3.3 종방향 응답과 시간 이력 추가

목표 속도를 낮추면 실차 속도도 즉시 낮아진다고 가정하지 않도록, 다음 요소를 실험 환경에 추가했다.

1. 목표 속도 명령의 가속·일반 감속 제한.
2. 명령 전달 지연과 1차 응답.
3. 실제 가속·감속의 서로 다른 한계.
4. 에피소드별 응답 파라미터 무작위화.
5. 현재 한 번의 스캔 대신 최근 라이다 4프레임 입력.

| 조건 | 가속 한계 | 감속 한계 | 응답 시정수 | 지연 |
| --- | --- | --- | --- | --- |
| nominal | 2.0m/s² | 3.0m/s² | 0.25초 | 0.10초 |
| stress | 1.5m/s² | 2.0m/s² | 0.40초 | 0.20초 |
| randomized | 1.5~2.5m/s² | 2.0~3.5m/s² | 0.15~0.40초 | 0.05~0.20초 |

이 값들은 **실측 보정값이 아닌 시뮬레이션 가정**이다. 모터 전류 제한·배터리 충전 한계·과전류 보호 정지·종방향 타이어 미끄러짐을 재현하는 전기 모델은 추가하지 않았다. 따라서 “관성을 완전히 재현했다” 또는 “전류 문제가 해결됐다”고 해석하면 안 된다.

관련 파일: `configs/experiment_6mps*.yaml`, `installation/f1tenth_gym/envs/longitudinal.py`, `utils/experiment.py`, `utils/env.py`.

### 3.4 전문가와 충돌 판정 검증

Pure Pursuit 전문가에는 곡률·제동거리·반응 지연을 고려한 선행 감속을 적용했다. 선행 감속을 끈 조건과 같은 시작 상태로 비교한 46회 시험에서는 적용 시 46/46회, 미적용 시 44/46회 완주했다. 미적용 실패 두 건은 Montreal이었다.

시뮬레이터의 기존 충돌 판정 문제도 수정했다.

- 장애물이 차체 안에 들어와 TTC가 음수가 된 경우를 놓치지 않도록 했다.
- 차체 경계 계산에서 축간거리 0.35m 대신 차체 길이 0.57m와 차량별 너비·라이다 위치를 사용했다.
- 접근 중인 벽의 TTC 판정에 적어도 한 시뮬레이션 스텝을 포함했다.
- 이 판정은 라이다·TTC 기반이며 완전한 연속 차체 충돌 해석은 아니다.

수정 후 전문가를 nominal/stress/randomized에서 각각 92회 검증해 **276/276회 완주**했다. 이후 23개 트랙에서 2랩씩 총 46랩, **164,733개 학습 사례**를 다시 수집했다.

수정 전후 데이터는 검증 서명이 달랐지만 실제 관측·정답 배열은 같았다. 기존 학습 출처는 보존하고 새 충돌 판정으로 별도 검증했다. 근거: [데이터 동등성 기록](sim6mps_dataset_equivalence_20261112.json).

## 4. 모델 5 — CNN과 복구 데이터 보강

### 4.1 학습 방법과 입력 구조

학습 방법은 **BC 기반 모방학습에 DAgger 방식의 복구 데이터 보강을 적용**한 것이다. IL은 모방학습의 큰 범주, BC는 전문가 입력·행동 쌍으로 지도학습하는 방법이다. CNN은 학습 방법이 아니라 신경망 내부 구조다.

- 기존 모델 3·4의 가중치를 이어받지 않고 CNN을 처음부터 학습했다.
- 모델 입력은 라이다 거리만 사용한다. 위치·트랙 이름·전문가 명령을 입력하지 않는다.
- 정상 주행 126,456개와 모델이 방문한 오차 상태의 전문가 정답을 사용했다.
- 복구 수집은 좌우 0.25m, 방향 0.10rad 범위의 시작 흔들림과 수집 중 전문가 개입을 포함한다.
- 복구 데이터 수집 주행 전체가 반드시 완주한 것은 아니다. 정상 전문가 완주 데이터와 실패 전 복구 사례를 구분했다.
- **최종 평가에서는 전문가가 제어에 개입하지 않는다.** 지도·중심선은 평가 점수 계산에만 사용한다.

프레임은 라이다 스캔 한 묶음이다. 5번은 최근 네 시각을 따로 유지하면서 **각 시각의 이웃한 방향 거리값 4개씩 평균**한다.

```text
각 시각: 1,080개 거리 → 이웃한 방향 4개씩 평균 → 270개
최근 4시각을 각각 유지 → 거리 특징과 시간 변화 특징 → CNN → 조향·목표 속도
```

시간상 4프레임을 평균해 한 프레임으로 만드는 것은 아니다. 외부 입력은 여전히 `4 × 1080 = 4320`개다. 시뮬레이션 프레임 간격은 0.025초이므로 가장 오래된 프레임과 최신 프레임 간격은 0.075초다. 실차의 실제 수신 간격은 별도 확인이 필요하다.

평균 축소는 중복 정보·계산량·측정 흔들림을 줄이려는 설계 선택이었다. **1,080개 모델에서 오버피팅을 확인한 뒤 바꾼 것은 아니며, 270개가 더 좋다는 동일 조건 비교도 하지 않았다.** 좁은 장애물·벽 모서리 정보 손실 가능성을 설명했고, 추후 원본 해상도 모델과의 비교 대상으로 남겼다.

실차 원본은 저장소 밖에 있으며 Git push에 포함하지 않았다. 파일 존재는 기록 완전성·오류 부재·무충돌을 의미하지 않는다.

## 10. 종료 시점의 상태와 다음 작업 인계

- 모델 5는 **11월 12일 Jetson에 배포하여 실차에 사용했다.** 오전 검증 보고서의 `physical_vehicle_validated: false`, `deployed_to_jetson: false`는 배포 전 스냅샷이며 오후의 사용 이력을 부정하는 것이 아니다. 다만 실차 사용과 모든 조건의 안전 검증 완료는 다르다.
- 노트북의 모델·코드 배포 커밋은 `ae3844f`다. 소프트웨어 기본 선택은 모델 2이며, 실차 시험은 `policy_file`을 지정하여 모델 5를 사용했다.
- Jetson에서 마지막으로 안내한 gain은 **5300**이다. 시험 중 Jetson의 gain 변경을 별도로 커밋·push했다는 증거는 없다. 노트북 기준 `vesc.yaml`은 **2500** 상태다. 다음에는 두 컴퓨터의 차이를 확인한 뒤 동기화·실행해야 한다.
- 마지막 5300 재시험은 **사용자 관찰로 약 5바퀴 후 충돌**했다. 3200의 추가 장애물 충돌과 다른 기록으로 다룬다.
- 실제 지면 속도, 최속 랩, 오류 당시 전류, gain별 완주율은 **미측정 또는 미분석**이다. 수치를 확정하지 않는다.
- 로컬 실차 기록 6개를 확인했지만 6.0/gain 2500 기록은 로컬 미확인이다. 실패한 5300 첫 시도도 이력에서 지우지 않고, 실패와 전송 보류 사실을 남긴다.
- 다음 작업 후보는 사용자가 분석 재개를 지시한 뒤의 동일 조건 비교, 4300 재실행 구간 분리, 5300 충돌 전 동작·명령 포화 확인, 독립적인 지면 속도 측정, 1,080개 입력 CNN과 270개 입력 CNN의 동일 조건 비교다. 현재는 원인이나 최적 gain을 확정하지 않는다.
